我在做什么What I work on

有一条问题一直贯穿我的研究：机器学习可以让哈密顿量预测得更快，但怎样才能接着计算电子结构、输运、光学响应等真正感兴趣的物理量？在大体系里，瓶颈往往从建立物理模型转移到了数值算法与计算基础设施。One question has followed me through several projects. Machine learning may predict a Hamiltonian quickly, but we still need to calculate the electronic structure, transport, or optical response we actually care about. At large scales, the bottleneck often moves from the physical model to the numerical methods and computing infrastructure around it.

我参与过 DeePTB 和 SLEM 这类学习量子算符的工作，也在做 VBCSR 这样的分布式稀疏计算工具，以及 AD-NEGF 和 DeePTB-NEGF 相关的量子输运计算。这些工作关注的问题不同，但彼此是连着的。That has led me to learned quantum-operator models such as DeePTB and SLEM; to distributed sparse-matrix software such as VBCSR; and to quantum-transport work including AD-NEGF and DeePTB-NEGF. They are different problems, but they connect.

为什么做软件Why I build tools

研究也越来越依赖能长时间自主运行的 Coding Agent。它们会读文章、修改代码、提交计算，却常常留下很难整理的脚本和日志。我开始做 flower，想把这些中间步骤留成可追踪、可复现的工作流。一个工具是否有价值，不只是它能算出结果，还在于别人能不能理解它是怎么算出来的。Coding agents can already read papers, modify code and run scientific jobs, but the scripts and logs they leave behind are often hard to make sense of. I started flower to preserve those steps as a workflow someone else can inspect and rerun. For me, a useful scientific tool should not only produce a result; it should also make clear how that result was obtained.
